# 보안 핫픽스 운영 적용 계획

이 문서는 적용 계획이다. 이 작업에서 Railway 변수 변경, Production 재배포, 운영 DB 접근, main 병합은 하지 않는다. 비밀 값과 코드 기본값 원문은 적지 않는다.

대상 리비전은 `main` = `develop` = `3aaf471`. 운영에는 이미 환경별 `JWT_SECRET`과 `APP_ALLOW_LEGACY_CREDIT_CHARGE=false`가 들어가 있다. 이 핫픽스는 그 변수를 유지한 채, 변수가 빠지거나 코드 기본값으로 되돌아가면 프로세스가 뜨지 않게 한다.

## 적용 전

1. production `JWT_SECRET`이 비어 있지 않고, 32바이트 이상이며, 코드 기본값과 다른지 확인한다. development 키는 production과 달라야 한다. 값을 로그나 티켓에 붙이지 않는다.
2. `APP_ALLOW_LEGACY_CREDIT_CHARGE`가 production에서 `false`인지 확인한다. `true`로 두지 않는다.
3. 현재 배포가 `3aaf471` 계열인지 확인한다. 이 핫픽스는 그 스키마만 가정한다. 새 Flyway 마이그레이션은 없다.
4. 배포 창에 사용자는 기존 access 토큰으로 계속 로그인된 상태일 수 있다. 키를 바꾸지 않으면 기존 토큰은 서명이 그대로 유효하다.

## 적용 시

1. 환경 변수는 바꾸지 않는다. 특히 `JWT_SECRET`을 비우거나 코드 기본값으로 덮어쓰지 않는다.
2. 이 Draft PR만 배포 승인 후 배포한다. PR #66 스택은 함께 배포하지 않는다.
3. 프로세스가 뜨지 않으면 배포를 중단한다. 기동 실패 문구는 키가 없거나, 32바이트 미만이거나, 퇴역된 코드 기본값이라는 뜻이다. 문구에 키 원문은 없다.
4. 배포 직후 무토큰 관리자 API는 401, 일반 로그인 사용자의 관리자 API는 403, 정상 로그인과 `GET /api/auth/me`는 200이어야 한다. 위조 토큰을 운영 서버에 보내지 않는다.

## 적용 후

1. 기존 사용자 access 토큰은 키가 같으면 만료 전까지 서명은 맞다. 권한은 토큰의 role claim이 아니라 DB `users.role`이다. `account_status`가 `ACTIVE`가 아니면 401이다.
2. `POST /api/credits/charge`는 403이다. 잔액과 원장은 이 호출로 변하지 않는다. 패키지 결제(MOCK 포함, 운영의 기존 결제 경로)만 크레딧을 늘린다.
3. 코드 기본값으로 서명된 토큰은 401이다.
4. production 키(86자)와 development 키(64자)는 모두 512비트 이상이므로 기존 jjwt `signWith(SecretKey)`와 같이 HS512로 검증한다. 키를 더 짧게 바꾸면 알고리즘이 바뀌어 기존 토큰이 거절된다. 이번 배포에서는 키를 바꾸지 않는다.

## 롤백

1. 애플리케이션만 이전 리비전으로 되돌릴 수 있다. `JWT_SECRET`과 `APP_ALLOW_LEGACY_CREDIT_CHARGE=false`는 유지한다.
2. 변수를 지우거나 코드 기본값으로 되돌리는 롤백은 금지다. 이전 코드는 변수가 없으면 코드 기본값으로 다시 서명한다.
3. 원장, Flyway, 결제 주문은 롤백 대상으로 수정하지 않는다.

## 세션

수정으로 세션 저장소를 추가하지 않았다.

- access JWT 만료는 24시간이다. refresh token 저장소와 재발급 API는 `3aaf471`에 없다. 만료되면 다시 로그인한다.
- `POST /api/auth/logout`은 `accessToken` 쿠키를 지운다. 서버 폐기 목록은 없다. 이미 발급된 Bearer 토큰은 만료 전까지 서명은 맞다. 다만 권한은 매 요청 DB 역할로 다시 계산한다.
- DB에서 역할을 바꾸면 다음 요청부터 반영된다. 재로그인은 권한 반영의 조건이 아니다. 로그인 응답과 브라우저에 남은 역할 표시는 발급 시점 값일 수 있고, `GET /api/auth/me`는 DB 역할을 반환한다. `APPLICANT`의 `/me` 표기는 기존과 같이 `USER`다.
- 비밀번호를 바꿔도 이미 발급된 access 토큰은 만료 전까지 유효하다. 이번 핫픽스는 그 폐기 기능을 넣지 않는다.
- 계정이 `SUSPENDED` 또는 `DELETED`이면 로그인과 기존 토큰 모두 401이다.
